# SocialSimulation 使用说明

## 环境与入口

工程使用 Unity 6000.6.2f1、URP、AI Navigation 和 Input System。打开 `Assets/SocialSimulation/Domains/Combined/CombinedSocialWorld.unity`，等待脚本与 NavMesh 资源导入完成，然后进入 Play Mode。该场景把校园、家庭、工作交易与社团放在同一个 `SimulationWorld` 中，包含 20 名学生、2 名教师、1 名教务负责人、2 名店员和 2 名工人，共 27 名 NPC。样例是通用服务的组合演示；新场景可以只装配所需领域模块。

若场景资源需要重建，使用菜单 `SocialSimulation/Samples/Generate Combined World`。此命令会重建场景中 `SocialSimulation Generated World` 根节点，覆盖该根节点下的手工改动。`SocialSimulation/Samples/Validate Combined World` 检查地区层级、交互点、NPC 身份和 NavMesh。最近一次编辑器重建的结构校验结果为 9 个地区、58 个交互点、27 名 NPC、3 个领域；运行和构建结果以[验证记录](验证记录.md)的最新复测为准。一般使用时直接打开已交付场景即可。

Game 视图左上角显示模拟时间、NPC/地区/活动数量和最近事件。`Pause/Resume` 暂停或继续统一时钟与导航，`Step` 即使暂停也推进一个逻辑 Tick；`x1/x30/x120` 设置每真实秒的模拟秒数。`Save/Load` 保存、恢复当前世界，路径是 Unity 的 `Application.persistentDataPath/SocialSimulation.<WorldId>.save.json`，Console 会打印实际绝对路径。组合场景 WorldId 为 `combined.demo`，独立社区为 `community.independent`。存档只适用于相同场景身份、内容清单与兼容图版本；替换内容后读取不兼容存档会报错。

`Assets/SocialSimulation/Domains/Combined/IndependentCommunity.unity` 是无校园模块的独立社区：7 名 NPC、4 个地区、家庭和工作交易两个领域，其中两名角色使用 Generic 骨骼。重建入口为 `SocialSimulation/Samples/Generate Independent Community`，会先重建组合样例再另存并裁出独立社区，请先保存自己的场景改动。该场景用于验证同一照护者完成早餐照护、工作领薪、购买和社团日程；模块通过 Inspector 显式绑定地区、集体、角色和动作图。

## 演示顺序

组合场景的显示时钟从 07:45 开始，每 Tick 推进 5 个模拟秒，默认速度为 30 倍。主要事件：

| 模拟时间 | 可观察内容 |
|---|---|
| 07:46 | 家庭早餐、照料任务和非正式规范传播；早餐开始时家庭成员收到家庭公告，当时离家而获知的成员会回家迟到加入，未获知者不会加入 |
| 07:50 | 学生接受或拒绝课程邀请，教师与店员启程，学生通过行为图申请座位并导航 |
| 08:00 | 两间教室开课；迟到者按会话状态加入 |
| 08:10 | 商店员工班次开始，完成后通过账本发放报酬 |
| 08:20 | 教务负责人巡视 |
| 08:45 | 课间 NPC 去走廊、商店，演示单座位竞争与学生原子购买；顾客采购到点后按个人知识决定采购或推迟 |
| 08:50 | 有权限的负责人发布走廊禁跑制度，部分学生知晓；店员班次结束后发放工资 |
| 08:51–08:55 | 店员用工资采购；不同评分可以让学生选择走或跑，目击形成证据后才生成违规与警告任务 |
| 09:00–09:10 | 第二节课与步行社团聚会；家庭、工作、社团身份在同一个 NPC 上继续生效 |

在 Play Mode 中暂停后手动调用 `WorkAndTradeDomainModule.SetShopServiceAvailable(false)` 再恢复，可以观察事件驱动的目标重评：顾客获知暂停即推迟，获知复业（公告、同地转述或记忆过期）后自动重启采购，无需任何脚本再次请求；观察器的目标评分区会显示每次重评采用的知识依据。

场景的课程、座位、经济、规范和会话是模拟事件；Animator 只呈现结果，不决定业务是否完成。Kenney 模型提供有效 Humanoid Avatar；生成器从 KayKit 动画 FBX 加载 11 个 Humanoid 片段并绑定示例 Controller，覆盖 Idle、Walk、Run、坐下/坐姿/起身、挥手、工作、交互、群体动作与持物姿态。这里的 `Talk` 使用挥手片段作通用交流提示，未实现口型或对白同步。片段导入与 Controller 绑定已有编辑器检查；实际运行画面及各业务触发路径须以最终 PlayMode 验证为准。动画和业务能力分别在 NPC 包中声明，见[资源与授权](资源与授权.md)。

可在 Play Mode 中选中 `SocialSimulation Generated World` 根节点下的 NPC/地区对象，检查 `SocialNpcMarker`、`SocialWorldMarker`、`SocialInteractionPoint` 和 `SocialNpcNavigation`。世界的实体状态由根节点上的 `SocialWorldRunner.World` 持有；可用工作台的轨迹和 Console 观察业务事件。

打开 `Tools/Social Simulation/Runtime Observer`，在 Play Mode 中从 NPC 下拉列表选择实例，或在场景层级选中带 `SocialNpcMarker` 的角色。观察器显示该 NPC 的身份与多重角色、需求、目标评分、活动、资源、动作阶段、图轨迹、规范和因果事件；可按事件类型筛选，或直接暂停、单步、调整时间倍率。观察器依赖运行中的 `SocialWorldRunner`，编辑模式只显示等待提示。

个人知识区显示来源、渠道、当前置信度和有效期；目标评分区保留决策当时的知识依据。可按主题、内容、来源或事件 ID 筛选；摘要区分总数、匹配数和最多 64 条显示数。多世界场景须在 Hierarchy 选择目标 NPC 或世界，运行控制和数据只绑定该 Runner；同 NPC ID 不跨世界匹配。完整操作与已验证边界见[运行观察器](运行观察器.md)。

## 行为图与规则图

打开 `Tools/Social Simulation/Graph Workbench`，选择已有的 `AttendCourse.asset` 或 `CorridorNoRunning.asset`，也可新建图资产。左侧节点库可搜索、点击添加或拖入画布；连接端口、拖动节点、选中节点后修改右侧参数。`Ctrl+C/Ctrl+V` 复制粘贴选择，`Ctrl+Z/Ctrl+Y` 撤销重做。使用 `保存` 写入资产，`校验` 查看结构、类型与引用诊断。无效草稿可保存，但不能应用到运行世界。

画布右键的“布局”菜单可创建注释、将所选节点与注释分组、从分组移出选择。分组标题、位置、尺寸、成员关系与注释内容随图资产保存，支持复制、删除和 Undo / Redo；删除分组保留成员节点。布局变化不改变执行版本或连线顺序。

为工作台指定已验证内容目录与 NPC 模板后，动作目录可按模板能力、骨骼、执行器和表现依赖筛选，并显示不兼容原因。应用前会递归检查子图。当前部分领域包只声明 ActionIds，没有向编辑器公开真实动作定义，这些条目会显示未知并禁用；需要先完成领域定义接线，不能仅凭动作名称认定可用。

行为图从 `入口` 连接 `顺序/选择/响应选择` 等控制节点，再连接 `行动`、`条件`、`等待`、`超时`、`冷却`、`有限重试` 或 `子行为图`。`行动` 节点的 `actionId` 必须有对应 `ActionDefinition` 与执行器；课程样例使用 `course.reserve_seat`、`course.move_to_seat`、`course.sit`、`course.attend`、`course.release_seat`。资源由动作 Scope 持有，可转交课程会话；动画事件不会直接提交考勤或经济效果。

规则图从 `事件` 连接 `适用范围`、`条件`，最后连接 `规范` 或 `效果命令`。走廊样例以目击事件和证据触发 `violation.warn`，实际是否构成违规、处理人是否有管辖权限仍由 `NormService` 检查。已发布规范、NPC 是否知晓、具体选择和违规后果分别记录。

工作台在 Play Mode 下按当前图的 DocumentId 和类型匹配实现 `ISocialGraphHost` 的模块，同时兼容 `IGraphWorkbenchRuntimeBridge`。多个宿主声明同一图时会显示歧义并拒绝默选。家庭和工作交易图位于各自 `Graphs/` 目录：`Care`、`ShiftAndWage`、`Purchase` 和 `ClubMeetup`，均通过动作图运行。行为图的“应用”模式只影响随后创建的实例；“重启实例应用”要求先暂停，清理旧动作与导航后重建，家庭/工作模块保留已接受日程和活动的进度。工资及交易仍由幂等账本保证只提交一次。规则图应用后，新事件使用新计划。更改图语义后请保存资产，再保存游戏；同一运行会话保留活动旧版计划，跨重启加载仍要求所有检查点对应版本可取得，否则明确拒绝。

规则图支持 AND / OR / NOT 以及半开时间窗 `[开始, 结束)`。右侧“试运行”输入事件、角色、地区、动作、证据和模拟秒数，显示逐节点真假、规范命中和拟提交命令，不修改实际世界。运行时节点显示中文状态；观察某 NPC 时可给节点设置断点，当前 Tick 完成后暂停。子行为图可进入编辑，再返回父图。

条件节点支持 `string`、`number`、`bool` 类型，以及相等、不等、大于、大于等于、小于、小于等于比较（允许操作由类型校验）。数字使用不依赖系统区域设置的小数点格式，拒绝 NaN / Infinity；单位必须与上下文显式声明一致，不会隐式换算。示例条件：字段 `speed`、类型 `number`、比较 `greater`、阈值 `1.5`、单位 `m/s`；领域传入 `context.TypedAttributes["speed"] = RuleFieldValue.Number(1.75, "m/s")`。数据类型或单位错误会产生诊断，不能借由 NOT / OR 反转为许可。

## 社会结构与内容包

打开 `Tools/Social Simulation/Social Structure Workbench`。新建结构图后，在左侧添加 NPC、集体、组织、地区、角色等节点；先在工具栏选连线类型，再连接节点；编辑节点 ID/属性，保存并校验。结构图可表达多重成员资格、角色、关系、授权与管辖，并由编译后的计划装配到 `SimulationWorld`。关系和组织不是 GameObject 层级的同义词。

打开 `Tools/Social Simulation/Content Catalog` 可扫描 `NpcPackageAsset`、`RegionPackageAsset` 和 `SocialDomainPackageAsset`。先创建或定位包资产，单包显示“就绪”后点击“注册”；注册前会用加入候选包的临时目录做联合预验证，通过才写入目录资产。最后使用“校验已注册内容”复核布局、版本、依赖、执行器和重复 ID。当前样例目录包含 2 个 NPC 包、8 个地区包、3 个领域包，最近一次编辑器联合校验通过；9 个场景地区实例中两间教室复用同一地区定义。注册规则、目录与 Prefab 层级见[标准资产包](标准资产包.md)。

地区 Prefab 根节点使用唯一 `SocialWorldMarker`；根下的 `Zones` 容器分组功能区，每个功能区带 `SocialRegionZone` 并拥有直属 `InteractionPoints` 容器，交互点带 `SocialInteractionPoint`。从已有场景对象创建地区包可用 `Tools/Social Simulation/Create Standard Region Package From Selection`；选中地区包后用 `Tools/Social Simulation/Instantiate Selected Region Package` 放入场景并自动写入新的 `RegionInstanceId`。同一地区 Prefab 的不同实例必须有不同地区实例 ID；交互点身份由地区实例 ID 与本地 ID 合成。

地区的营业时间、成员/角色要求和容量由目标准入检查执行，请用 `SocialWorldRunner.CanEnterRegion` 查看拒绝原因。入场请求及到达时都会复核，关闭地区会清理当前占用与活动。这是逻辑准入控制，不会自动建立物理门或禁止其他路线穿越；需要物理封锁时还须配置门、障碍物或导航区域。地区重开只恢复资源的 `RegionAvailable`，不会改写独立的 `Active`；手动停用的交互点保持停用。完整规则见[标准资产包](标准资产包.md)。

## 接入其他场景

1. 按[标准资产包](标准资产包.md)准备并注册所需 NPC、地区和领域包，完成目录联合校验。NPC 可以使用 Humanoid 或 Generic Avatar；两者的 Animator 与动画素材应按各自骨骼类型配置。
2. 在新场景的世界根对象上放 `SocialWorldRunner` 与**恰好一个** `SocialCatalogProvider`，给 Provider 指定 `SocialContentCatalogAsset`。没有内容 Provider 的世界会拒绝启动。把需要的领域模块作为同根组件装配；家庭、校园和工作交易仅是可选示例领域。准备可达的 NavMeshSurface。
3. 将地区包 Prefab 放在世界根下，给每个 `SocialWorldMarker` 写唯一 `RegionInstanceId`、对应的 `RegionDefinitionId` 与 `PackageId`；功能区和交互点结构保持与包定义一致。地区实例化工具会自动分配地区实例 ID 与包 ID。
4. 为 NPC 要加入的每个集体添加 `SocialCollectiveMarker`，显式填写集体 ID、显示名、是否正式、是否组织。把这些标记放在世界根的子树中；没有定义的成员集体会被拒绝。
5. 将 NPC 包 Prefab 放在世界根下，给每个 `SocialNpcMarker` 写唯一 `NpcInstanceId`、对应的 `PackageId`、显示名和成员集体 ID。显式指定 `PrimaryCollectiveId` 与主角色；一个 NPC 在其他成员集体的角色通过 `MembershipRoles` 单独绑定。可配置人格原型，初始化时按世界种子与实例 ID 生成并持久化。Prefab 的 `NavMeshAgent` 默认禁用，由 `SocialNpcNavigation` 在 Surface 注册后启用和管理；参见[标准资产包](标准资产包.md)。启动时 Provider 先构建注册表，Runner 再核对实例与已注册包，并从包清单取得 NPC 的模板/能力以及地区语义/容量；不匹配会拒绝启动。
6. 在新场景运行 PlayMode 检查业务轨迹、动画、导航与存档。`Validate Combined World` 菜单针对交付组合样例，包含其 27 人和三个领域的断言，不是其他场景的通用验收器。

### 领域导航点与超时

`WorkAndTradeDomainModule` 在 Inspector 中提供下列本地交互点绑定，也可在 `Initialize` 前调用 `ConfigureNavigation(shiftPoint, purchasePoint, clubPoint, memberPoint)`：

| 字段 | 默认值 | 用途 |
|---|---|---|
| `shiftPointId` | `counter` | 员工工作位置 |
| `purchasePointId` | `queue` | 顾客购买位置 |
| `clubPointId` | `chat` | 社团组织者集合位置 |
| `clubMemberPointId` | `run.1` | 社团其他成员集合位置 |

这些 ID 必须与绑定地区的交互点精确一致，例如样例使用 `run.1`。空字符串或 `null` 表示地区根位置；已经在目标地区内的领域动作可直接开始。指定了不存在的点会拒绝导航，不会自动改走地区中心。社团其他成员的导航请求被拒绝时，模块取消相应聚会图与职责，并发布 `community.club.travel_refused`，可在事件轨迹中定位绑定或准入问题。

购买动作的总预算 `purchaseActionTimeoutSeconds` 默认 **1200 个模拟秒**，覆盖校验、导航和购买执行；可在 Inspector 中修改，或在 `Initialize` 前调用 `ConfigurePurchaseTimeout(float simulatedSeconds)`。该值必须为有限正数。30 倍模拟速度下，1200 个模拟秒约为 40 个真实秒；NavMesh 的移动速度仍按真实时间计算。布置较远目标或提高时间倍率后，应按实际行走时长乘模拟倍率，再加业务执行时长与余量配置预算，并确保日程截止时间允许完成。

通用导航请求 `SocialWorldRunner.RequestTravel(..., timeoutSeconds)` 另有默认 **1800 个模拟秒**的导航预算，只接受有限正数。导航截止和业务动作截止分别生效，以先触发者为准；提高购买动作预算不会自动延长通用导航预算。超时会结束导航并返回失败，不会无限等待。

## 常见问题排查

| 现象 | 先检查什么 |
| --- | --- |
| NPC 不移动 | 场景是否有可用 NavMeshSurface；`SocialNpcNavigation` 是否注册；`RequestTravel` 返回 false 的原因（地区未开、容量已满、交互点不存在）。可在事件轨迹中查找 `agent.travel_failed` |
| 读档被拒绝 | `LoadedRegionIds` 是否与当前加载的地区集合一致；包版本/指纹是否改变；领域检查点 schema 是否匹配（家庭 v2、工作交易 v3）；错误信息会给出具体不匹配项 |
| NPC “知道”了不该知道的事 | 个人知识只能通过 `Observe`/`Announce`/`DeliverSystemNotice`/`Relay` 进入；确认没有把全局事件或世界查询当作 NPC 输入 |
| NPC 不再尝试某个目标 | 目标选择只读个人知识：在观察器中查看该 NPC 的知识条目与目标评分区的 `KnowledgeAssessments`；矛盾信息会拒绝目标，失败冷却与承诺窗口也会压后选择 |
| 目标从不自动重评 | 确认领域模块已在 Initialize 与读档后注册 `world.GoalReevaluation` 规则；模块禁用（OnDisable）会注销规则；容量淘汰不产生遗忘事件，只有到期/衰减遗忘会触发 |
| 关系数值变化但没有事件 | 关系衰减是被动漂移，不产生事件；`Relate` 即强化并重置衰减计时；可在存档中核对 `DecayedFor` |
| 图应用被拒绝 | 行为图必须让每条成功路径恰好执行一次所需动作；“重启实例应用”要求先暂停世界；图版本与检查点对应关系见上方行为图一节 |

## 存档和验证

点击 `Save` 后可暂停、单步、继续、再点击 `Load` 比较逻辑时间、活动、资源占用和事件轨迹。存档记录世界快照、包版本与语义指纹、已加载地区集合、场景检查点、角色位置、待完成导航和动作检查点；不会直接序列化协程或 Animator 内部状态。写盘先保存临时文件并 Flush，再替换主文件，已有主文件另留 `.bak`。

当前 Core 世界快照 **v3**、Unity 存档封装 **v5**、动作检查点 v3、行为检查点 v2、家庭检查点 v2、工作交易检查点 **v3**。工作交易 v3 保存服务暂停状态，拒绝旧 v2。Core 和运行封装的升级包含知识快照与承诺结算历史；旧开发存档明确拒绝，尚无自动迁移路径，不能靠改版本数字补齐缺失历史。加载时，`LoadedRegionIds` 必须无重复，并与当前已加载地区 ID 集合精确匹配，顺序不限。多加载或卸载一个地区也会导致拒绝，应先恢复匹配的场景加载状态。修改场景实体 ID、删除必要图版本或更换内容包同样可能使旧存档不兼容；加载前校验会给出具体错误。

每项待完成导航保存绝对模拟时间 `Deadline`；读档后保留原截止点，只重新申请剩余时间。已经到期或无法重新发起的导航按失败处理，反复读档不会延长预算。领域动作通过 `GetTravelStatus(agentId, placeId, actionInstanceId)` 读取 Runner 提交的结果，恢复后继续原导航；结果按 NPC 保存最近一项。动作检查点保留自身的截止时间，子图检查点分层序列化，避免 Unity JsonUtility 的递归深度截断。

测试入口是 Unity `Window > General > Test Runner` 的 EditMode/PlayMode。逻辑压测入口为 `Tools/Social Simulation/Run 100-300 NPC Logic Benchmark`，报告写到 `Docs/Benchmarks/LogicBenchmark.md`。该压测只测 100/300 个逻辑 NPC 的 Tick、评分和资源操作，不含渲染与 NavMesh，不可当作完整场景帧率。具体已执行验证和限制见 [验证记录](验证记录.md)。角色和动画来源、授权与导入状态见 [资源与授权](资源与授权.md)。

### 重复执行验证

项目提供 `Tools/Validate-SocialSimulation.ps1`，连接当前工程已运行的 Unity Editor。先停止其他 Test Runner 或构建任务并退出 Play Mode；脚本会 Refresh 资源并等待导入、编译稳定，再请求域重载和启动测试。运行测试期间保持 Assets 不变。脚本需要当前环境可调用 `unity` CLI，不会为了测试自动再开一个编辑器。

在工程根目录执行：

```powershell
.\Tools\Validate-SocialSimulation.ps1 -Phase All -ReportTag 20260930-full
```

`All` 顺序执行 EditMode、PlayMode、Windows 构建与双场景 Player 检查。可用 `-Phase EditMode|PlayMode|Build|Player` 单独执行阶段，`-TestFilter` 限定 Editor 测试；每轮用不同的 `ReportTag` 保留证据。结果与 Player 日志写入 `Docs/Validation`。只运行 `Player` 时使用已存在的构建，所以源码改动后应先构建或执行 `All`。

Player 检查使用 `-batchmode -nographics`，验证两场景的 NavMesh、NPC 注册、移动、保存恢复与运行错误；这不包含画面、动画视觉质量或帧率验收。2026-10-26 起脚本已兼容 Windows PowerShell 5.1（eval 与 `--scenes` 参数不再含会被 PS 5.1 剥离的内嵌引号），PowerShell 7 同样可用；本批 356/356 EditMode、15/15 PlayMode、Windows 构建与双场景 Player 均已通过该入口复现，实际范围见[验证记录](验证记录.md)。脚本会在测试前请求域重载，避免连续筛选沿用残留 TestRunner 状态。零测试的 0/0 报告会使脚本失败，不能作为通过结果。

## 知识、人格与治理扩展

- [知识与信息传播](知识与信息传播.md)：通过 `world.Knowledge` 注册渠道、观察、公告和转述；`GoalCandidate.KnowledgeConditions` 只读取当前 NPC 的个人知识。未知信息可配置为允许尝试、拒绝或扣分。工作交易已接入暂停服务观察、转述与推迟采购；NPC 对商店可用性的个人知识一旦变化（获知复业、转述或记忆过期），`world.GoalReevaluation` 会自动重跑其采购选择，无需日程或显式请求；真正到达柜台时仍按客观服务状态结算。家庭早餐创建时经家庭频道公告，获知的家庭成员回家后会迟到加入活动，未获知者不会加入。
- [人格原型](人格原型.md)：配置稳定原型、偏差和相关维度；人格参与偏好，不代替岗位资格、能力或权限。
- [组织治理与承诺](组织治理与承诺.md)：通过 `world.Governance` 产生可接受/拒绝的任务请求，通过 `world.Agreements` 建立多方同意与履约历史。现有领域的旧承诺默认 `ManagedLifecycle=false`，需显式迁入后才能获得新生命周期保证。
- 未强化的 NPC 关系按可配置半衰期向中性漂移（默认半衰 2 天、宽限 1 小时），重温关系即重置；设置与已衰减量随存档保存。

这些通用服务已有 Editor 回归；知识采购已通过真实导航、动画、存档与账本的 PlayMode 专项，事件触发重评与关系衰减各有 Core 与领域级回归，并在 2026-10-26 的全套 EditMode/PlayMode/构建/Player 报告中覆盖。集成其他领域时，仍须把真实到达、动作完成、证据、权限与经济结果接到服务，并验证完整链路。
