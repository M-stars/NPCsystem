# 知识与信息传播

## 作用与边界

`SimulationWorld.Knowledge` 是纯 C# 的个人知识服务。它保存 NPC **通过实际渠道获知的陈述**，包括原始事件、主题、对象、内容、来源、最后传达者、发生/获知时间、地区、置信度、情绪权重、衰减与保护标记。全局 `Trace` 中有事件，不会让所有 NPC 自动知道。

知识条目不等同于世界真相，也不会自动生成 `NormService.Evidence`、违规记录或处罚。NPC 不知道一项制度，不影响这项制度的客观有效性；收到消息也不代表一定相信或服从。行为评分应读取个人知识、置信度和人格，再作选择。

实现文件为 `Assets/SocialSimulation/Core/Knowledge.cs`。`ObserverKnowledge` 只提供当前 NPC 的查询副本，适合注入 NPC 决策上下文。权威领域模块保有知识服务的写入接口；不要把可写服务或全世界查询作为普通 NPC 的认知输入。

## 三种信息入口

| 入口 | 用途 | 校验与结果 |
| --- | --- | --- |
| `Observe(observerId, worldEvent, ...)` | 直接看见或听见正在发生的事件 | 必须是真实轨迹里的事件，内容一致、同一逻辑地区且不早于当前一个 Tick 的时间窗口；Unity 感知适配器仍须先验证距离、视线等具体可感知条件 |
| `Announce(channelId, publisherId, topic, subjectId, value, ...)` | 公告、广播、机构通知、一般发言 | 创建稳定的原始事件 ID，按当前受众与发布权限投递；返回实际获知人数和未写入人数 |
| `DeliverSystemNotice(agentId, originEventId, topic, subjectId, value, sourceId, channelId, ...)` | 已验证发布/送达的制度、排班或设备记录适配器 | 调用者负责稳定的原始事件 ID 和实际送达；服务继续校验注册渠道、有效来源、发布权限、受众和同地约束；记录为 `SystemNotice`，不会伪装成直接目击 |

`DeliverSystemNotice` 的可选 `occurredAt` 应传原事件发生时间，例如 `norm.PublishedAt`。同一事件的后续通知继续使用同一 ID。新的制度版本或新的事件需要新的 ID。调用者不能每次转述生成新 ID 来增加“证据数量”。

所有接收接口会返回明确结果：`Learned`、`Updated`、`Unchanged`、`Unknown`、`Denied`、`Expired`、`Capacity`、`Cooldown` 或 `Invalid`。调用方应处理容量或权限失败，避免把未送达当成已获知。

## 配置渠道

```csharp
world.Knowledge.RegisterChannel(new KnowledgeChannel
{
    Id = "workshop.staff.notice",
    CollectiveId = "workshop.team",
    Audience = KnowledgeAudience.AssignedRoles,
    RequiredRoleId = "workshop.worker",
    PublisherAuthorityAction = "notice.publish",
    RelayCooldownSeconds = 60,
    TransmissionConfidence = 0.9f,
    RetentionSeconds = 86400,
    ConfidenceHalfLifeSeconds = 3600
});

// 岗位分配必须明确包含该信息渠道。
workerRole.InformationChannels.Add("workshop.staff.notice");
```

| 字段 | 规则 |
| --- | --- |
| `Audience = Public` | 所有在世 NPC 可接收，仍检查渠道本身和可选所属集体是否有效 |
| `CollectiveMembers` | 必须当前有效成员，检查成员开始和结束时间 |
| `AssignedRoles` | 在有效成员基础上，必须有有效角色且角色的 `InformationChannels` 包含渠道 ID；可额外限制 `RequiredRoleId` 与 `ObjectScopeId` |
| `PublisherAuthorityAction` | NPC 发布和通过该渠道转述时必须拥有所属集体内的当前权限；对象权限按渠道 `ObjectScopeId` 校验 |
| `RequiresSamePlace` | 发送者与接收者的逻辑地区必须相同且非空；机构身份本身没有身体，不能用于此类同地发言 |
| `AllowRelay` | 是否允许已知信息通过该渠道转述 |
| `TransmissionConfidence` | 每次传达的置信度乘数，范围 `(0, 1]`，不能通过渠道增加置信度 |

有效集体可以通过自己的渠道发布系统公告，不能冒用其他集体。机构身份的发布入口供权威领域模块调用；普通 NPC 必须以自身 ID 调用并通过权限校验。

`RegisterChannel` 复制配置并拒绝重复 ID；查询配置也是副本。运行中关闭渠道使用 `SetChannelActive`。退出组织、角色到期、撤权、组织解散都会在下一次投递时立即重新校验。已合法获取的历史知识保留，不会因离职被凭空清除。

原始受众限制保存在 `OriginChannelId`。受限信息经过公共频道转述时，接收者仍须满足原渠道资格；不能用频道转换绕过成员/岗位权限。泄密、窃听、冒名等行为需要独立领域动作、证据与后果，普通 `Relay` 不隐式实现这些行为。

## 个人查询与转述

```csharp
ObserverKnowledge ownKnowledge = world.Knowledge.ForAgent(npcId);
foreach (KnowledgeRecord report in ownKnowledge.Query("shop.state", shopId))
{
    float confidenceNow = report.ConfidenceAt(world.Time);
    // 结合需求、人格、已有承诺决定是否采用这条信息。
}

KnowledgeDelivery outcome = world.Knowledge.Relay(
    senderId, receiverId, originalEventId, "conversation.local");
```

先显式注册 `conversation.local`，例如设置 `RequiresSamePlace = true`。对话会话应在双方接受并实际会合后调用转述；知识服务不会替代邀请、会合与对话轮次协调。

每人对同一 `OriginEventId` 只保存一项记录。同源多条传播路径只保留质量更高的记录，不相加、不当作多个独立目击；较弱的传闻不能覆盖本人直接观察。转述保存原始来源、原始时间、原渠道和原寿命，增加深度并设置最后传达者。消息转一圈回来不会重置衰减时间、延长寿命或再次增信。

默认每位发送者最多保留 256 条有效冷却记录。冷却键是“发送者、接收者、原始事件”，切换频道不能绕过。上限满时拒绝新的受冷却转述，不能淘汰仍有效的冷却。默认最多 8 跳，超过后拒绝继续传播。这些时间都使用仿真时钟，暂停时不计时。

## 遗忘、容量与保护

默认每人最多 64 条知识，遗忘阈值为 `0.05`。置信度按原始衰减时间作指数半衰：

```text
当前置信度 = 初始置信度 × 0.5 ^ ((当前时间 - 衰减起点) / 半衰期)
```

半衰期为 0 表示不按置信度衰减。普通记录在保留期结束或当前置信度低于阈值后遗忘。查询会即时忽略过期记录，Tick 负责回收。容量满时淘汰最低显著性的未保护记录，显著性考虑置信度与情绪权重；稳定事件 ID 用于平局排序。

Tick 期的到期/衰减遗忘会发出 `knowledge.forgotten` 事件（载荷为主题、对象与原始事件 ID，US 分隔），事件轨迹可见并参与目标重评；容量淘汰发生在存入新记录时，不产生遗忘事件。`Protected` 用于重要承诺、制度告知等需要保留的记录：不自动遗忘、不被容量淘汰，也不产生遗忘事件，但它的数值置信度仍按配置计算。全部条目受保护时，新记录返回 `Capacity`，不会无限扩充。受保护知识并不使已经过期的制度或承诺继续客观生效；客观生命周期由对应服务处理。

容量、冷却上限和最大传播深度宜在初始化时配置。若需要运行时降低容量，应先实施业务上的归档策略，避免已保护的个人记录超过新容量。服务不将被移除 NPC 的全部知识转给其他角色；其他人的来源记录继续保留已离场 NPC 的稳定 ID。

## 知识参与目标选择

`GoalCandidate.KnowledgeConditions` 可声明需要同时满足的个人知识条件。`DecisionService.Select` 只查询当前 NPC 的 `ObserverKnowledge`，按主题/对象、置信度阈值、可选原始来源、消息寿命和最大年龄筛选，再采用**原始发生时间最新**的合格记录。同一时间采用置信度更高的记录；同一时间与置信度的矛盾消息进入 `Conflicting`，按未知策略处理。迟到的旧转述不会覆盖较新消息。

```csharp
candidate.KnowledgeConditions.Add(new GoalKnowledgeCondition
{
    Topic = "service.availability",
    SubjectId = serviceId,
    ExpectedValue = "available",
    MinimumConfidence = 0.5f,
    UnknownPolicy = UnknownKnowledgePolicy.AllowAttempt
});
```

| 未知策略 | 行为 |
| --- | --- |
| `AllowAttempt` | 未获知、已过期或可信度不足时，仍允许尝试目标 |
| `Reject` | 没有有效个人信息时拒绝这个目标 |
| `Penalize` | 保留目标，并从评分扣除 `UnknownScorePenalty` |

有效记录与期望值矛盾时拒绝目标；配置非法时也拒绝。受保护历史虽保留在记忆中，超过消息有效期后不再作为条件依据。知识条件不含商店等领域专属逻辑，可用于设施、约见、工作安排、交通状态等明确陈述。

`DecisionTrace.Candidates[].KnowledgeAssessments` 记录条件结果、允许与否、当前置信度、扣分、解释和原始知识副本。副本保留来源、最后传达者、原始事件、渠道和原始时间；用户可以追溯 NPC 为什么尝试或放弃目标。条件和评估副本不共享调用方的可变集合。

知识条件描述“什么时候选这个目标”；`world.GoalReevaluation` 负责“什么时候重新选”：学到、更新与遗忘都会按领域注册的规则自动重跑选择。用法与边界见[扩展指南](扩展指南.md#事件触发的目标重评)。

### 工作交易领域中的接线

`WorkAndTradeDomainModule` 的顾客采购事件与店员采购日程先经过 `SelectPurchaseGoal`。已知暂停服务者选择 `trade.purchase.defer`；未知者仍启动采购图。采购动作到达柜台后检查客观服务状态，暂停时不扣钱、不发货，并通过真实事件记录该顾客的直接观察。其他 NPC 不会自动得知。

- `SetShopServiceAvailable(available, announce)` 是领域权威入口；默认样例保持服务可用，工资/采购流程继续正常运行。
- `PublishShopAvailability(publisherId)` 要求发布者实际位于商店，且拥有该商店的 `trade.availability.publish` 权限。默认店员初始化时获得此权限。
- 公告渠道 `<shopPlaceId>.availability.notice` 只发送给同地区 NPC，默认有效 1800 仿真秒。
- `RelayShopAvailability(sender, recipient, originalEventId)` 使用 `<shopPlaceId>.availability.conversation`，双方必须同地，保留原始来源与寿命，置信度乘以 0.9。对话主持者应在实际完成会合和交流时调用。
- `TryStartCustomerPurchase()` 可由外部剧情或交互再次请求采购。它重新评估个人知识；已完成采购不会重复结算。

**事件触发的重评（2026-10-26 起）：**顾客对 `trade.service.availability` 的个人知识一旦变化（学到、更新或保留期遗忘），`GoalReevaluationService` 会自动重跑其采购选择：获知复业或记忆过期后无需显式请求即重启采购；真正到达柜台时仍按客观服务状态结算，失败会再次形成现场观察。因此现在的重评入口为：知识事件、采购日程和显式再次请求三类。店员因个人知识被拒的本次采购日程仍不会自动重建；需要持续采购/换店行为的领域应提供日程或重排机制。

工作交易领域检查点现为 **v3**，保存 `ShopServiceSuspended`；旧 v2 开发检查点明确拒绝。个人知识仍由世界快照保存，完整读档同时恢复领域状态与个人知识，不重新广播公告。Core 条件由候选目标生成时声明，不是额外世界真相副本。

## 在观察器中查看知识与依据

`Tools/Social Simulation/Runtime Observer` 的个人知识区只查询所选 NPC。它显示原始事件、来源链、渠道、当前置信度、发生/获知/到期时间、保护与转述状态；可按主题、陈述、来源、渠道或原始事件 ID 筛选，先筛选再限制最多 64 条，并显示总数、匹配数和显示数。

目标评分区另列 `KnowledgeAssessments`：条件是否允许候选、未知策略、扣分，以及当次决策采用的知识副本与置信度。这里是决策时历史，个人知识区是当前状态，两者不会相互覆盖。过期的受保护记录明确显示历史状态，仍不能充当有效的新决策依据。

选择绑定具体世界和 NPC；相同 NPC ID 出现在另一个世界时不会串线。世界卸载、未注册 Marker 或孤立角色不会自动回退到其他同 ID 实例。相关隔离和终态诊断已有回归，个人筛选与 NPC 切换已在真实 Play Mode 验证。操作步骤与截图见[运行观察器](运行观察器.md)。

## 保存与恢复

世界快照包含 `KnowledgeSnapshot`（版本 1）：渠道、个人条目、来源链的必要字段、衰减、保护、容量参数和未结束冷却。`Capture` 输出稳定顺序与深复制；`Restore` 先完整校验临时容器，再替换服务状态。不存在的个人、重复原始事件、缺失渠道、非法时间/置信度、重复冷却及容量超额会拒绝恢复，不留下部分状态。

当前 Core 世界快照 v3、Unity 运行存档 v5 明确拒绝缺失知识检查点或版本不符的旧开发存档，没有自动迁移。后续迁移工具必须明确处理旧知识的来源与渠道；不能静默把 `KnownNormVersions` 当成来源、渠道和冷却全部正确的新知识，也不能只改版本数字绕过校验。
