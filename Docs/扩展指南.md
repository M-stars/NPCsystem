# SocialSimulation 扩展指南

## 分层与状态所有权

`Assets/SocialSimulation/Core` 是不引用 UnityEngine 的仿真内核：稳定 ID、时间与事件、社会结构、资源和账本、活动、规范、决策、日程及快照。`Graph` 编译并执行行为图/规则图，`Actions` 管理动作状态和资源作用域，`UnityRuntime` 负责 NavMesh、GameObject 与 Animator 表现，`Domains` 提供家庭、校园、工作交易示例，`Authoring` 与 `Editor` 提供包资产和画布。运行程序集不引用 Editor。组合场景只负责装配领域；新增医院、城镇或其他场景时可复用内核与内容合同。

定义和实例需要不同 ID：包 ID 标识可复用内容，定义 ID 标识包中的概念，实例 ID 标识世界中的 NPC、集体、地区、会话、资源 Token 等。一个地区包声明一个地区根定义，根下有功能区和交互点；本地功能区 ID 与本地交互点 ID 在该包内分别唯一。不同地区可复用本地 ID，但组合后的 `RegionInstanceId/LocalId` 在一个世界中必须唯一。持久状态以实例 ID 相连，不依赖对象名或 Unity InstanceID。

状态只由对应服务修改：`SocietyService` 管成员、角色、授权、关系和承诺；`ResourceService` 管临时槽位/预约；`EconomyService` 管库存、账户与原子交易账本；`ActivityService` 管多人会话；`NormService` 管发布、知晓、证据、违规和处理；`DecisionService` 负责候选目标评分；`ScheduleService` 管跨领域义务的时间窗口与冲突；`SimulationWorld` 驱动固定 Tick 与事件。新增领域代码应通过这些服务提交变化，而不是同时改写多个集合。`KnowledgeService` 管个人知识和传播渠道，`GovernanceService` 管授权任务请求与派生指标，`AgreementLifecycleService` 管显式同意、履约和结算历史；用法分别见[知识说明](知识与信息传播.md)与[治理/承诺说明](组织治理与承诺.md)。`GoalReevaluationService` 把个人知识变化转成领域注册的目标重评，见下文[事件触发的目标重评](#事件触发的目标重评)。原有 `Society.CreateCommitment` 默认不自动纳入新生命周期，领域应显式迁入。

## 添加 NPC 包

1. 准备 FBX，并确定 `Humanoid` 或 `Generic` 骨骼路线。`Content Catalog` 的“从选中 FBX 创建标准 NPC 包”提供自动识别和手动指定，复制模型并生成统一目录及逻辑根 Prefab。NavMeshAgent 驱动位置时关闭 Animator Root Motion，避免双重位移。Prefab 中 Agent 默认禁用，由 `SocialNpcNavigation` 在 Surface 注册后接管启停，详见标准包约定。
2. 在 `NpcPackageAsset` 设置稳定包 ID、版本、`BodyProfile.Rig`、身体尺寸与速度、角色 Prefab 和有效同类型 Avatar。按[标准资产包](标准资产包.md)整理 `Model`、`Rig`、`Animations`、`Materials`、`Textures`、`Prefab`。显式声明 `locomotion.walk` 等能力、`BodyConstraint` 和执行器；新增社会语义能力需由领域代码实现。
3. 对确有片段的能力配置 `AnimationBindingProfile` 和 Animator Controller；必需表现缺失会让包校验失败，映射状态还需绑定实际 Motion。Humanoid 动画可按 Unity 重定向规则跨相容角色使用；Generic 需要相容骨架。当前 Kenney 样例绑定了 KayKit 的移动、坐姿、挥手、工作、交互、群体与持物片段，其中挥手仅作交流提示。
4. 单包 `Validate()` 与布局检查成功后，在 `Content Catalog` 点击“注册”。工具先将候选包加入临时目录做联合预验证，通过才写入正式 `SocialContentCatalogAsset`；随后再运行“校验已注册内容”。`ContentRegistry.RegisterBatch` 对内存注册状态原子提交清单，重复导入相同版本是幂等操作；包版本或定义冲突应先调整资产。

`NpcPackageAsset` 代表内容声明，不自动赋予角色或组织权限。场景以 `SocialCollectiveMarker` 定义集体是否正式、是否组织；NPC 的 `PrimaryCollectiveId` 和 `MembershipRoles` 显式指定其成员角色，不从领域 ID 前缀推断。一个 NPC 可以同时拥有多个 Membership 和 RoleAssignment。系统运行时仍需检查目标、状态、资源与权限。

## 声明包依赖与版本范围

2026-09-30 新协议已通过 **343/343 EditMode**，包含新增的 Core 54 项与 Authoring 11 项回归；真实目录联合校验也已通过。2026-10-26 已用当日源码补齐 PlayMode 15/15、Windows 构建（0 错误、1 条配置警告）与双场景 Player（运行错误 0）验收。完整格式见[标准资产包](标准资产包.md#当前依赖与版本能力)。

三类包 Inspector 都提供 `Dependencies` 和 `Dependency Requirements`。前者填只需存在的包 ID；后者填 `PackageId` 与 `VersionRange`，支持 `*`、精确数字版本、`[min,max)`、`[min,)`。一到三段数字按补零比较，每段最大为 `4294967295`；不支持 `^`、`~`、比较器、预发行/build 标签，不是完整 SemVer。

新增范围项自动使包 manifest 使用 schema v2，包自身的 `Version` 必须为数字；未使用范围的旧 v1 可继续采用非空不透明版本，指纹保持兼容。范围会进入新指纹；更改约束后旧存档可被拒绝。Core 世界快照 v3 与运行封装 v5 不变，这次没有自动迁移、安装或升级依赖。

代码可调用各包的 `ConfigureDependencies(ids, requirements)`；方法复制输入，不替代保存和校验。生成 `DomainManifest` 时通过 `ToPackageManifest()` 保留完整依赖与 schema。自定义场景应复用 Runner 已校验的目录，避免另建丢失 NPC/地区依赖的缩略清单。Combined 示例已按此调整，联合回归已纳入 343 项通过报告。

目录联合注册拒绝重复依赖、自循环/循环、缺失依赖和不匹配版本，失败不提交部分内容。需要一批互相依赖的包时使用 `ContentRegistry.RegisterBatch`；不要依靠清单添加顺序绕过校验。注册表每个包 ID 只有一个实际版本，不会替调用方解算或安装一个“合适版本”。

## 添加地区包与交互点

创建 `RegionPackageAsset`，绑定一个地区 Prefab 与唯一的 `RegionDefinition`。定义中的 `Zones` 声明功能分区的本地 ID、语义标签和容量；每个 `InteractionPointDefinition.ZoneLocalId` 必须引用已声明的分区。Prefab 根节点放唯一 `SocialWorldMarker` 并绑定地区包 ID，其直属 `Zones` 容器按分区组织，每个分区直属 `InteractionPoints` 容器；`SocialRegionZone` 与 `SocialInteractionPoint` 的 ID、标签、动作和容量要与定义一致。带 `SocialCatalogProvider` 的世界启动时先构建目录，再扫描实例标记，建立 `PlaceState` 和 `ResourceSlot`；未绑定已注册包、层级与定义不符、重复或空实例 ID 均会拒绝初始化。完整目录和层级见[标准资产包](标准资产包.md)。

同一地区 Prefab 放入场景多次时，为每份实例分配不同 `RegionInstanceId`；本地 `seat.01` 可以复用，最终槽位 ID 则为 `地区实例 ID/seat.01`。地区容量、功能区容量、交互点容量、邀请/占用和所有权是不同概念；定义中不要求地区容量等于功能区容量之和。预约席位使用有期限的 `ResourceToken`，动作退出或会话结束时释放。

## 添加领域机制

创建 `SocialDomainPackageAsset`，填写包 ID/版本及角色、关系、活动、动作 ID。家庭、校园、工作交易领域通过共享服务协作；业务状态机、实际执行器和样例初始化写在 `Domains/<领域>`，不把 `CourseSession` 之类字段塞进 Core。内容目录负责声明、依赖和冲突校验；场景仍需装配 `SocialWorldRunner`、恰好一个 `ISocialContentProvider`、领域组件、集体定义、地区与 NPC 实例，目录不会从清单自动生成业务逻辑。

新行为动作应有 `ActionDefinition`、执行器 ID、目标和所需能力，并实现 `IWorldActionAdapter.Step` 与 `OnExit`。`ActionGraphHost` 在验证、预约、移动、执行和提交阶段推进；通过 `ActionExecutionContext` 预约本地或复合 Scope 资源，并用 `TryCommitEffect` 防止同一效果重复提交。跨节点长期占用必须转给复合 Scope 或会话；异步导航/动画回调使用代数校验，取消后旧回调不能提交。可恢复动作实现恢复钩子与语义目标检查。

新多人活动由 `ActivityService.Create/Invite/Respond/Start/JoinLate/Complete/Cancel` 组成。只有在场且接受的参与者计入开场人数；邀请不等于出席。家庭照料、劳动和交易等关系可用独立 `Commitment` 记录参与方与义务，组织命令通过任务和授权请求表达，不能强制重写成员决策。

正式规范先在 `NormService.Definitions` 定义，由有 `policy.publish` 授权的主体 `Publish`；用 `Inform` 传播知晓。`KnownPenalty` 会影响目标评分，仍允许 NPC 违反。违规则需要可追溯 `ObservationEvidence`，然后 `RecordViolation`，有管辖 `violation.handle` 授权者才可 `RequestResponse`。规则图的 `RuleEffect` 只发出命令，业务服务负责最终校验。

## 事件触发的目标重评

`SimulationWorld.GoalReevaluation`（`Core/GoalReevaluation.cs`）把“个人知识变化”翻译成“重跑该 NPC 的目标选择”。服务监听 `knowledge.learned`、`knowledge.updated` 与 `knowledge.forgotten`（Tick 期到期/衰减遗忘，容量淘汰不产生事件），匹配领域注册的“代理+主题+主体（可通配）”规则，去重后调度 `goal.reevaluation.due` 事件，在下一 Tick 末尾调用处理器。处理器内部应照常调用 `world.Decisions.Select(...)` 并执行所选目标；服务不注入世界真相，也不替领域执行动作。

```csharp
// 领域模块 Initialize / RestoreScenarioState / OnEnable 时注册；Detach 时注销。
world.GoalReevaluation.Register(customerId, "trade.service.availability", shopPlaceId,
    () => TryRestartCustomerPurchase());
world.GoalReevaluation.Unregister(customerId, "trade.service.availability", shopPlaceId);
```

规则不在快照中保存：读档后由领域模块重新注册；未触发的重评调度事件会随世界快照恢复并在新世界触发，若届时规则已重新注册即照常执行。同一规则的多条知识变化合并为一次重评；代理离场后到达的调度事件被跳过。现有两个真实接线：工作交易顾客的可用性知识（获知复业或记忆过期后自动重启采购，客观柜台校验不变），家庭依赖者的早餐公告（获知后回家并 `JoinLate`，未获知不会加入）。

## 关系衰减

`SocietyService.Tick`（已接入世界 Tick）对未强化的 `SocialRelation` 的 `Liking/Trust` 按半衰期向中性漂移；`Familiarity` 不衰减。`ConfigureRelationDecay(halfLifeSeconds, graceSeconds)` 配置：半衰期 0 表示关闭，正数至少 1 秒；宽限期内的接触重置漂移（`Relate` 即强化）。已衰减的时长记录在 `SocialRelation.DecayedFor`，与设置一起进入世界快照，读档后从记录继续而不是重新计算。衰减是被动漂移，不产生事件；结构图编译器的 `Relate` 增量语义不受影响。

## 资源、会话与移除清理

本地动作资源用 `TryReserveLocal`；需要跨叶节点保留的资源用 `TryReserveForScope`。所有租期使用仿真秒。`ResourceService.Request` 会保存每条等待请求自己的租期；`TryAcquireMany` 对同一作用域已持有的 Token 支持幂等重复申请，任何资源不可用或参数非法时不会新增部分占用。

把 Token 交给多人会话时，调用 `ActionExecutionContext.TryTransferToSession` 或 `ActivityService.AttachResource`。服务同时检查参与资格、会话状态和 Token 所有者，然后记录到参与者条目。仅将 `OwnerScopeId` 改为某个字符串不构成完整转交。已完成或已取消的会话拒绝接收 Token；活动中途退出后人数不足时会取消会话并释放其临时资源。

取消复合行动调用 `ActionGraphHost.Cancel`；模块退出时先停止接收事件，再取消活动图和导航等适配请求，最后注销 Tick 系统。`RemoveSystem` 在 Tick 中也可安全调用：本 Tick 尚未执行的已删除系统会跳过，新加入的系统从下一 Tick 执行。同一 `Order` 的系统按注册顺序执行。

```csharp
world.EventPublished -= OnWorldEvent;
actionHost.Cancel(world.TickIndex);
world.RemoveSystem(domainSystem);
```

实际模块可能拥有多个行动实例，应取消全部实例。家庭与工作交易模块的 `Detach` 提供了取消图实例和注销系统的示例。重新启用时需要重新注册系统和事件；不要为同一个模块重复添加事件处理器。

移除 NPC 使用 `SimulationWorld.RemoveAgent`。它取消该 NPC 的资源等待、释放该 NPC 的 Token、退出活动、取消日程并撤销成员身份和相关授权；共享会话中其他人的 Token 不会因为作用域相同而被错误删除。Unity 视图、导航请求和动作主机仍应由对应适配层清理。尚未完成的承诺与资产需要领域给出结算或移交方案，不应当作临时 Token 删除。

## 分域角色、授权和制度

岗位授予的权限应明确绑定 `RoleAssignment.Id`。独立授权可以不绑定角色；退出集体时仍会撤销成员在该集体的授权。转授权需要父授权允许委托，不能扩大地区或对象范围，结束时间不能超过父授权；运行时检查完整祖先链，而不只检查最近一级。

```csharp
var role = world.Society.AssignRole(agentId, shopId, "trade.manager", departmentId);
var grant = world.Society.Grant(shopId, agentId, "policy.publish", shopId,
    placeScopeId: shopPlaceId,
    durationSeconds: 3600,
    canDelegate: true,
    roleAssignmentId: role.Id);

world.Society.RevokeRole(role.Id); // 撤销此角色绑定的权限及其转授权链
```

一个 NPC 的其他角色和独立授权不会因为撤销此角色而一并失效。跨身份职责使用 `ScheduleDefinition.RequiredRoleId`，并按需要设置 `RequiredCollectiveId`、`RequiredObjectScopeId`；否则同名角色的组织和对象范围不会被日程进一步限制。

有组织归属的地点应设置 `PlaceState.OwnerCollectiveId`。规范的 `SubjectScope` 有三个值：

| 值 | 适用对象 |
| --- | --- |
| `Members` | 发布集体的成员 |
| `Jurisdiction` | 位于该集体所属地点的行动者 |
| `MembersOrJurisdiction` | 满足成员或地点条件之一；默认值 |

地区 tag 只表达地点用途，不能单独代表组织管辖。发布规范时会复制定义，之后编辑模板不会改变已发布版本。新版本仍需发布并通过渠道通知 NPC。已获知的 `Prohibit` 降低对应动作收益，`Require` 和 `Prefer` 提高对应动作收益；要求型规范的“不履行证据”仍需领域机制实现。

使用 `OverridesNormId` 表达明确覆盖。覆盖链不得循环，非正式规范不能借覆盖字段取消正式规范。当前客观处理使用有效覆盖关系；NPC 只有获知覆盖版本后才据此改变决策。这保留了“制度已经变更，但某人尚不知道”的情况。

## 事件因果链与预算

世界同时限制 `MaxCascadeDepth`、`MaxEventsPerRoot` 和 `MaxEffectsPerRoot`。深度或预算超限会产生包含根因、父事件和尝试操作的诊断。增加预算前先排查规则反馈环；预算值也会进入快照。

事件直接派生新事件时传 `parent`。延迟操作应在源事件仍有效时通过 `Schedule` 排队，调度项会保存父信封，跨 Tick 与读档保留根因预算。

```csharp
world.Emit("inspection.requested", observerId, subjectId, requestId,
    placeId: placeId, parent: sourceEvent);
world.Schedule(world.Time + 5, "inspection.retry", observerId, subjectId,
    placeId: placeId, payload: requestId, parent: sourceEvent);
```

当该根因已经没有待处理事件或调度项，世界会回收其计数。之后重用旧父信封会被 `CASCADE_CLOSED` 拒绝，不会重新从零开始计算预算。真正独立的新外部输入可以作为新的根事件提交。

规则命令使用稳定效果键，并将源信封传给效果提交：

```csharp
var key = ruleId + "|" + sourceEvent.Id + "|" + subjectId + "|response";
world.TryCommitEffect(key, () => ApplyValidatedResponse(), parent: sourceEvent);
```

重复效果键不会再次执行；同步回调重入同一个键也会被拒绝。回调中的状态变化仍需先做完整业务校验：幂等包装不会自动回滚任意已经发生的 C# 副作用。动作内部使用 `ActionExecutionContext.TryCommitEffect`，由动作实例 ID 和效果阶段组成去重键，并检查取消代数。

实际 `IRuleEffectHost` 应把源事件传入 `TryCommitEffect`。在该同步回调期间，业务服务内部调用的 `Emit`、`Schedule` 和嵌套 `TryCommitEffect` 会自动继承源根因；显式传入另一个父事件时，以显式参数为准。回调退出或异常后恢复外层上下文，后续独立外部事件不会被误归入旧根因。异步回调发生时同步上下文已经结束，仍须使用显式信封或提前排队的调度。

`ScheduledWorldEvent.HasParent` 是调度事件是否具有父信封的保存标记。Unity 的 `JsonUtility` 可能把空引用恢复为空对象，因此不能单凭 `Parent != null` 判断根因；恢复流程按 `HasParent` 还原可选父信封。扩展存档协议时，对同类可空数据也应使用明确判别字段，并补真实 JSON 往返测试。

## 自定义图节点与版本

节点描述在 `Graph/NodeDescriptor.cs`，文档类型在 `Graph/GraphDocument.cs`，校验与编译在 `Graph/GraphCompiler.cs`。添加节点时同步补齐编译规则、运行解释、编辑器参数面板和 EditMode 测试。`GraphDocument.DocumentId` 长期稳定，保存修改时递增 `Version`；已编译计划不可在原地改写，行为实例保留其计划版本。无效草稿不能替换运行版本。

运行时图工作台通过 `IGraphWorkbenchRuntimeBridge` 与场景模块通信；组合示例的应用入口是 `CombinedDemoScenario.TryApplyBehaviorGraph` / `TryApplyRuleGraph`。行为图可仅供新实例使用，或在暂停时取消旧实例并重建；规则图影响后续事件。运行实例绑定原计划的版本和内容 Revision，不能把新图结构直接套入旧运行栈。黑板变量有稳定 ID、类型、作用域、读写权限和存档策略；改显示名不会改变变量身份。社会结构图是另一类资产；编译计划可装配集体、组织、成员、角色、关系与授权，新的业务数据仍须由领域服务校验。

## 存档版本与内容一致性

在完整 Tick 边界同时捕获世界、行为图、动作和领域状态。`WorldPersistence.Capture` 拒绝在 Tick 或效果回调执行期间保存；`Advance` 和 `StepOne` 也不能在这些回调中重入。恢复顺序是先创建世界及权威资源占用，再恢复领域和动作语义检查点，最后恢复 Unity 表现。不能让全部动作重新争抢已经保存的资源。

| 数据 | 当前版本 | 说明 |
| --- | --- | --- |
| `SimulationSnapshot` | 3 | 保存世界服务状态，包含个人知识与承诺结算历史；拒绝旧快照 v2 |
| `BehaviorCheckpoint` | 2 | 子树采用独立 `SubtreeJson` 片段，避免 Unity 对递归对象序列化深度的截断 |
| `ActionGraphCheckpoint` | 3 | 与新版行为检查点配套；拒绝旧动作检查点 v2 |
| `SocialWorldRunner.SaveEnvelope` | 5 | 记录世界、包清单/指纹、已加载地区集合、姿态与行程截止/提交结果；拒绝旧封装，无自动迁移 |
| 家庭领域检查点 | 2 | 保留照护活动与图状态 |
| 工作交易领域检查点 | 3 | 保存服务暂停状态与图进度；拒绝旧 v2 |
| 包 `PackageManifest` | 1 / 2 | 无范围可保持旧 v1；范围要求使用 v2，包自身为数字版本。EditMode/PlayMode/构建/Player 四阶段均已通过 |

包指纹通过 `ContentRegistry.GetPackageFingerprint(packageId)` 获取，使用 SHA-256，数值格式不受系统区域设置影响。Unity 读档会对比已注册 manifest 的集合、版本和指纹；版本相同但内容不同也拒绝恢复。该指纹覆盖 manifest 中的身体、能力、动作、动画语义绑定和地区定义；新包协议还包含范围要求。它不包含 FBX 或 Animator Controller 文件内容。需要锁定美术与表现文件的发布流程，还应保存相应资产依赖校验信息。

旧开发存档没有自动迁移保证。正式发布前应固定协议；之后新增必需字段、改变所有权或修改图结构时，先提供迁移与回退方案。保留不兼容存档原文件，不能以静默忽略字段或重新开局代替成功恢复。

个人记忆也属于存档状态。`AgentState.Remember` 会复制输入记录，保持事件 ID 去重和容量上限；如果所有现有记录均受保护，会返回 false。重要义务仍须在承诺/义务记录中独立保留，领域代码应按需要处理记忆满额结果。

## 测试建议

至少给新增机制做一条失败与回滚用例：例如座位竞争、取消后 Token 释放、交易余额不足不写账本、无权限发布被拒绝、无目击证据不产生违规、不兼容图草稿保留旧计划、存档恢复不重复提交效果。跨领域修改还要在组合场景验证同一 NPC 的家庭、工作、采购和社团链路。性能报告区分纯逻辑 Tick 与完整 Unity 场景的导航、动画和渲染；未验证的规模不要写成性能承诺。

包依赖协议的 2026-09-30 EditMode 为 **343/343** 通过，2026-10-26 的 PlayMode、Windows 构建与 Player 证据见[验证记录](验证记录.md)；事件触发目标重评与关系衰减批次为 **356/356** EditMode 与全套平台证据。新增纯逻辑不变量主要在 `CoreInvariantRegressionTests`，动作生命周期与恢复在 `ActionLifecycleTests`，事件重评与衰减在 `GoalReevaluationTests`、`KnowledgeTests` 与 `SocialDecayTests`。

## 尚需完成的通用能力

新增领域时，请先检查[Core / Actions 验收差距矩阵](Core验收差距矩阵_20260927.md)。其中列明了当前实现、具体回归测试、调用方接线责任和未满足的硬要求，知识、治理、承诺与地区协议已有基础服务及对应回归；仍需其他领域接线、资源权利模型、规则争议策略和长时归档。事件触发的目标重评与关系衰减已在本指南说明，EditMode 356/356、PlayMode 15/15 与 Windows 构建/Player 证据见[验证记录](验证记录.md)。知识重评的已知边界：因个人知识被拒的日程不自动重建，容量淘汰不产生遗忘事件。

家庭、工作交易和校园能够组合运行，证明了当前协议的复用方式。新的社会业务仍需要相应领域执行器、编辑器配置与失败路径验证；已有测试通过不能替代新业务或任意人口规模的验收。
